路径与产物交互改造设计

目标：把绝对路径从用户主交互中降级为内部细节，同时保留本地工作流需要的真实文件路径能力。

设计原则

  • 前端不再把绝对路径作为主要展示内容，默认展示文件名、目录名、状态和动作。
  • 前端打开文件时只提交产物 key，例如 finalVideo.video，服务端负责解析真实路径。
  • 所有路径推导集中到服务端路径模块，避免路由文件继续膨胀。
  • 项目级工作目录作为新增能力引入，但首轮保持兼容：已有视频仍可在原视频旁边生成产物。
  • 模型、Token、临时目录等环境路径从硬编码迁移到配置读取，默认值继续偏向 D 盘。

范围

阶段交付不做
产物契约 新增 artifact key、摘要字段、服务端解析函数和打开接口。 不更改现有脚本参数格式。
前端体验 结果行显示文件名/目录名，提供打开、复制路径、显示完整路径。 不引入 Electron 或浏览器原生无法支持的文件选择能力。
项目目录 为新项目记录 workspaceDirectory，并提供统一计算入口。 不自动迁移历史产物，不移动用户原视频。
环境配置 读取 data/settings.json 覆盖运行环境路径。 不在本轮做完整设置页。

服务端结构

新增 server/project-paths.js，负责从视频记录和设置生成产物表。路由层只消费产物表，不再散落路径拼接逻辑。产物对象包含：

  • key：稳定标识，例如 englishDubbing.mixedTrack。
  • path：服务端内部真实路径。
  • kind：file 或 directory。
  • label：面向用户的中文名称。
  • displayName：默认展示的文件名或目录名。

前端结构

FileResult 和 DirectoryResult 合并到统一的产物行思路：主展示是 label + displayName + 状态，按钮触发 openArtifact(key)。完整绝对路径只在展开详情、复制路径、tooltip 中出现。

测试策略

  • 新增 Node 单元测试覆盖 artifact key 解析、路径摘要生成、打开接口拒绝未知 key。
  • 继续运行 npm run build 覆盖前端构建。
  • Python 测试依赖 pytest，当前系统 Python 未安装；本轮不往 C 盘安装依赖。
