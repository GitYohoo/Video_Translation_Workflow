后端任务执行层第一阶段设计

目标：在不改变现有 API 和工作流行为的前提下，从 server/index.js 提取可测试的任务执行公共层与任务路由。

范围

  • 新增 server/task-runner.js，统一处理进程启动、日志转发、取消、完成、失败和任务状态持久化。
  • 新增 server/routes/job-routes.js，承载任务列表、任务详情和取消接口。
  • BS-RoFormer 作为第一个迁移样板，验证单进程工作流可以脱离 server/index.js 中的重复生命周期代码。
  • OCR、英文配音等多阶段流程本阶段不迁移，避免一次改动多个执行模型。

任务执行接口

const runner = createTaskRunner({ jobStore, taskRegistry });
const task = await runner.start({
  videoId,
  workflow,
  logPath,
  activeTasks,
  activeKey: videoId,
  command,
  arguments: args,
  spawnOptions,
});

start() 在返回前完成任务持久化、日志流创建、进程启动、活动任务登记和取消处理器注册。进程事件在后台更新同一个任务对象。

状态与错误规则

  • 启动成功后状态为 running。
  • 退出码 0 写入 completed。
  • 非零退出码或进程启动错误写入 failed，保留清晰错误文本。
  • 取消时先标记 cancelled，再终止当前进程树，避免 close 事件覆盖取消状态。
  • 所有终态都从活动任务表和任务注册表中移除，并只结束一次日志流。

任务路由接口

createJobRouter({ findVideoById, jobController }) 返回 Express Router。路由负责项目存在性检查、HTTP 状态码和 JSON 响应；任务业务规则仍由 jobController 负责。

测试策略

  • 使用伪子进程和内存输出流测试任务执行器，不启动真实模型。
  • 覆盖成功、非零退出、启动错误、取消四条生命周期路径。
  • 使用临时 Express 服务和原生 fetch 测试任务路由的 200、202、404 与错误转发。
  • 迁移 BS-RoFormer 后运行全部 Node 测试、生产构建和浏览器页面检查。

后续阶段

本阶段稳定后，再让 task runner 支持多阶段命令序列，迁移 OCR、英文配音与单条重配；随后拆分其他 workflow routes 和 workflow services。
