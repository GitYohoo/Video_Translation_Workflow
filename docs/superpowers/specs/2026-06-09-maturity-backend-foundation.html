成熟化改造第一阶段：后端基础设计

目标：先把后端从“一个大文件能跑”推进到“有清晰数据访问边界和可持久化任务状态”的结构，为后续设置页、任务恢复、前端拆分打基础。

本阶段范围

模块本阶段做什么暂不做什么
Catalog 抽出视频项目目录读写模块，集中处理 videos.json、排序、查找、原子写入。 不引入数据库，不改变现有 videos.json 位置。
Job Store 新增 data/jobs 下的任务状态读写模块，定义稳定 job id、状态字段和日志路径。 不一次迁移所有工作流，只先完成基础能力和一个样板流程。
Workflow 样板 先把 BS-RoFormer 任务状态接到 job store，保留内存任务兼容运行中状态。 不改脚本参数和输出目录策略。
测试 用 Node 内置 test runner 覆盖 catalog 和 job store 的核心契约。 不往 C 盘 Python 环境安装 pytest。

设计决策

  • 继续使用文件存储，符合本地工具定位，避免过早引入 SQLite 或外部服务。
  • 任务状态使用 JSON 文件，路径为 data/jobs/<jobId>.json，方便人工排查。
  • job id 使用 <videoId>_<workflow>，同一视频同一流程保持稳定，重新运行会覆盖状态。
  • 所有写入采用临时文件 + rename，延续 catalog 现有原子写入思路。
  • 本阶段不做 UI 新入口，只让现有状态 API 能从持久化 job 恢复失败/完成信息。
