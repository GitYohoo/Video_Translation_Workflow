公共仓库安全清理与文档完善设计

日期：2026-06-23

目标版本：0.2.18

1. 目标

在不破坏当前本机使用方式和其他用户部署能力的前提下，清理不适合出现在 GitHub 公共仓库中的本地配置，强化忽略规则，完善仓库首页文档，并把当前已暂存的六个功能文件纳入 0.2.18 版本说明。本轮仅完成本地修改与验证，不提交功能变更，不推送远端。

2. 当前状态

  • 实际 Git 仓库位于 Video_Translation_Workflow 子目录。
  • 当前分支为 simplified-workflow，远端为 GitHub 仓库。
  • 已有六个暂存文件：package.json、package-lock.json、server/index.js、src/main.jsx、src/styles.css、tests/simplified-page.test.mjs。
  • 现有功能修改包括界面精简、桌面双栏独立滚动、最终成片内嵌播放及对应测试。
  • 当前 Git 历史扫描未发现真实 API 密钥、访问令牌、私钥或个人邮箱。
  • .claude/settings.local.json 是本机工具权限配置，不应继续由公共仓库跟踪。
  • README 徽章仍显示 0.2.14，与当前代码版本不一致。

3. 清理方案

项目 处理方式 兼容性保证
Claude 本机配置 将 .claude/settings.local.json 从 Git 索引移除并加入忽略规则。 本地文件继续保留，不影响当前环境。
环境与密钥文件 忽略 .env、本地 settings、Token、证书、私钥和常见凭据文件。 保留 data/settings.example.json 作为可复制的公开示例。
运行数据 继续忽略模型、缓存、日志、任务状态、视频索引、构建和发布产物。 程序运行时自动创建所需目录，不删除本机已有数据。
D 盘默认路径 保留不含用户名的通用默认路径，并在 README 中说明可配置项。 符合项目优先使用 D 盘的约束，也允许其他用户覆盖。
历史记录 不重写 Git 历史。 扫描未发现真实秘密，避免不必要的强制推送和提交哈希变更。

4. README 设计

保留 GitHub 识别所需的 README.md 文件名，正文使用 GitHub 兼容的 Markdown 与 HTML 组合排版。README 将以中文为主，保留简洁英文项目简介，并补齐以下内容：

  • 项目定位、当前成熟度和本地优先的隐私边界。
  • 主要功能与完整视频翻译流程。
  • Windows、Node.js、Python、FFmpeg、CUDA 与模型相关前置条件。
  • 源码启动、Electron 桌面启动和发布打包命令。
  • 运行配置文件的复制方法、字段说明和 D 盘默认目录。
  • Hugging Face Token 只通过本地文件配置且不得提交的安全说明。
  • 运行数据、模型、项目产物与源码目录的边界。
  • 0.2.18 中现有六个暂存文件对应的用户可见更新。
  • 测试命令、常见问题、已知限制和贡献前检查。

5. 版本策略

将 package.json 与 package-lock.json 从 0.2.17 更新到 0.2.18，同时同步 README 版本徽章。此次递增用于覆盖当前功能改进、安全清理与文档更新。

6. 验证方案

  1. 运行 Node.js 完整测试套件：npm run test:node。
  2. 运行现有 Python 单元测试。
  3. 运行生产构建：npm run build。
  4. 扫描所有已跟踪文件和 Git 历史中的常见密钥、Token、私钥、个人路径与邮箱模式。
  5. 检查忽略规则，确认本地配置、运行数据、模型、日志和发布产物不会被 Git 跟踪。
  6. 检查最终差异，确保不删除本机设置和运行数据，不混入仓库上层的个人字幕与网络配置。

7. 提交与远端边界

本轮不推送 GitHub。设计说明可单独进行本地提交，以满足设计留档要求；实际功能、安全清理、 README 和版本更新保持为本地工作区变更，等待用户以后明确要求同步远端。

8. 非目标

  • 不重写 Git 历史。
  • 不删除本机模型、依赖、视频、日志或用户设置。
  • 不改变现有工作流业务逻辑，除非验证发现安全或可用性缺陷。
  • 不安装或调用 GitHub CLI，不创建 Pull Request，不推送分支。
