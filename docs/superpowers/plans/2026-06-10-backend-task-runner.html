后端任务执行层第一阶段实施计划

目标：提取可测试的单进程任务执行器和任务路由，并用 BS-RoFormer 验证迁移方式。

架构：路由只处理 HTTP，控制器处理任务业务规则，task runner 处理进程生命周期。工作流仍负责输入校验、命令参数与状态响应。

技术栈：Node.js ESM、Express 5、node:test、原生 fetch。

任务 1：任务路由行为基线

文件：新增 tests/job-routes.test.mjs、新增 server/routes/job-routes.js、修改 server/index.js。

  1. 先写测试：项目不存在返回 404；列表返回控制器结果；详情缺失返回 404；取消返回控制器结果。
  2. 运行 node --test tests/job-routes.test.mjs，确认因模块不存在而失败。
  3. 实现 createJobRouter({ findVideoById, jobController })，每个处理器使用统一的项目查找函数。
  4. 从 server/index.js 删除三条内联任务路由并挂载 Router。
  5. 运行单测和全部 Node 测试后提交 refactor: extract job routes。

任务 2：单进程 task runner

文件：新增 tests/task-runner.test.mjs、新增 server/task-runner.js。

  1. 先写成功退出测试，期望任务持久化为 completed、清理注册表和活动任务。
  2. 运行测试确认 createTaskRunner 未定义。
  3. 实现依赖注入接口：
createTaskRunner({
  jobStore,
  taskRegistry,
  spawnProcess,
  createOutput,
  terminateProcess,
  now,
})
  1. 依次用失败测试增加非零退出、启动错误和取消行为。
  2. 每条测试先确认红灯，再添加最小实现并确认绿灯。
  3. 运行全部 Node 测试后提交 feat: add single process task runner。

任务 3：迁移 BS-RoFormer

文件：修改 server/index.js，必要时补充 tests/task-runner.test.mjs。

  1. 让 BS-RoFormer 保留输入检查和命令参数组装，生命周期交给 task runner。
  2. 删除该流程中的手工日志流、spawn 事件、注册和终态写入代码。
  3. 验证运行中重复请求仍返回已有状态，退出错误文本保持为 处理进程退出码：N。
  4. 运行全部 Node 测试、node --check server/index.js 和 npm run build。
  5. 提交 refactor: run bs roformer through task runner。

  1. 启动开发服务，调用任务列表和任务详情 API。
  2. 在浏览器打开现有项目，确认工作流卡片、状态和错误区正常。
  3. 运行 git diff --check 和 git status --short，确保没有遗漏改动。
