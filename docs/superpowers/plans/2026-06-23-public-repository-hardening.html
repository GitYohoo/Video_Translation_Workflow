公共仓库安全清理与文档完善实施计划

执行要求：逐项执行并更新任务状态；本轮不提交实际修改，不推送远端。

目标：将仓库整理为适合以后公开同步的状态，完善 README，并把现有功能更新纳入 0.2.18。

方法：保留本机文件和运行数据，只改变 Git 跟踪边界；README 明确依赖、配置、目录、安全和验证方式。

技术栈：Git、Node.js、React、Electron、Express、Python、PowerShell。

文件变更范围

文件动作职责
.gitignore修改阻止本地配置、凭据、模型、缓存、日志、构建和运行数据被误提交。
.claude/settings.local.json仅从 Git 索引移除本机文件保留，但以后不进入公共仓库。
README.md重写作为 GitHub 首页，提供中文主文档、英文简介、安装配置和安全边界。
package.json修改版本更新为 0.2.18。
package-lock.json修改锁文件根版本与项目版本同步。
现有六个暂存文件保留保留界面精简、独立滚动、最终视频播放及测试，不回退用户修改。

任务 1：确认执行环境和基线

  1. 确认当前不是链接 worktree，并在当前分支执行。 
    git rev-parse --git-dir
git rev-parse --git-common-dir
git branch --show-current
git status -sb

    预期：Git 目录与公共目录均为 .git；分支为 simplified-workflow；六个功能文件保持暂存。

  2. 确认依赖已经安装。 
    Test-Path node_modules
node --version
npm --version
python --version
ffmpeg -version

    预期：node_modules 存在，Node、npm、Python 和 FFmpeg 均可调用。

  3. 运行修改前的完整基线测试。 
    npm run test:node
python -m unittest discover -s tests -p "test_*.py" -v

    预期：Node 与 Python 测试均为零失败。若失败，先判断是否来自现有暂存功能改动。

任务 2：强化公共仓库边界

  1. 扩充 .gitignore。

    保留现有规则，并增加以下类别：

    # 本机工具配置
.claude/
.idea/
.vscode/

# 环境变量、凭据与本地证书
.env
.env.*
!.env.example
*.pem
*.key
*.p12
*.pfx
*.jks
*token*
*secret*
*credential*

# 本地应用配置
data/settings.json
data/desktop-settings.json

# Python 与测试缓存
.pytest_cache/
.coverage
htmlcov/

# 操作系统和编辑器临时文件
.DS_Store
Thumbs.db
*.swp
*.tmp

    Token 规则只作用于文件名；公开示例文件 data/settings.example.json 不受影响。

  2. 取消跟踪 Claude 本机配置，同时保留本机文件。 
    git rm --cached -- .claude/settings.local.json
Test-Path .claude/settings.local.json
git check-ignore -v .claude/settings.local.json

    预期：文件仍存在于磁盘，Git 状态显示删除，且忽略规则命中 .claude/。

  3. 验证公开示例仍被跟踪。 
    git ls-files data/settings.example.json
git check-ignore data/settings.example.json

    预期：示例文件仍在跟踪列表中，第二条命令不输出路径。

任务 3：重写 GitHub 首页 README

  1. 将 README 更新为 0.2.18，并保留 GitHub 所需文件名。

    README 使用 Markdown 与 GitHub 兼容 HTML，结构固定为：

    • 项目标题、0.2.18 徽章和简洁中英文简介。
    • 适用范围与“本地优先但 Gemini 翻译需要联网”的准确隐私说明。
    • 当前工作流：音轨分离、OCR、WhisperX、翻译校对、VoxCPM、成片导出。
    • 0.2.18 更新：精简翻译/配音/成片界面、双栏独立滚动、最终视频直接播放、安全清理。
    • Windows 10/11、Node.js、Python、FFmpeg、NVIDIA CUDA 的环境要求。
    • 源码开发命令：npm install、npm run dev、npm run desktop。
    • 复制 data/settings.example.json 到 data/settings.json 的配置步骤。
    • 配置字段：VoxCPM Python、临时目录、Hugging Face Token 文件路径。
    • D 盘默认目录和可配置说明。
    • 测试、构建和发布命令。
    • 敏感信息与运行数据禁止提交清单。
    • 项目目录结构、已知限制、排障和贡献检查清单。
  2. 核对 README 命令与项目脚本一致。 
    npm pkg get version scripts
rg -n "0\.2\.18|npm run test:node|npm run build|npm run release|data/settings\.json" README.md

    预期：版本、命令和配置路径均可在 README 中找到。

任务 4：同步版本号

  1. 将项目版本从 0.2.17 更新为 0.2.18。

    同时修改 package.json、package-lock.json 顶层版本和锁文件根包版本，不改变依赖版本。

  2. 验证三个版本来源一致。 
    npm pkg get version
rg -n '"version": "0\.2\.18"|Version-0\.2\.18' package.json package-lock.json README.md

    预期：项目清单、锁文件和 README 均显示 0.2.18。

任务 5：完整验证

  1. 运行完整测试。 
    npm run test:node
python -m unittest discover -s tests -p "test_*.py" -v

    预期：全部测试通过，零失败。

  2. 运行生产构建。 
    npm run build

    预期：Vite 构建退出码为 0，输出进入已忽略的 dist/。

  3. 扫描当前跟踪文件与 Git 历史。

    扫描模式包括私钥头、GitHub/OpenAI/Google/AWS 密钥格式、常见凭据赋值、用户目录和邮箱；依赖锁文件中的维护者邮箱作为第三方元数据排除。

    预期：除已知依赖元数据外，没有真实凭据或个人路径。

  4. 检查差异质量和忽略边界。 
    git diff --check
git diff --cached --check
git status -sb
git status --ignored --short

    预期：无空白错误；本地配置和运行数据被忽略；上层目录个人文件不属于仓库。

  5. 确认本轮不进行发布操作。 
    git log -1 --oneline
git remote -v

    预期：除已确认的设计说明提交外没有新增实际修改提交；不执行 git push 或 PR 操作。
