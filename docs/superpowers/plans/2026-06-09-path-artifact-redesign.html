路径与产物交互改造实施计划

目标：分阶段完成路径输入、路径展示、打开文件、项目目录和运行环境配置改造，并在每个稳定节点提交 git。

架构：先抽出服务端路径契约，再改前端消费方式，最后引入工作目录与环境配置。每一步都保持现有工作流可运行。

技术栈：React、Express、Node 内置 test runner、Vite。

任务 1：产物路径模块与测试

  • 新增 server/project-paths.js，集中管理路径推导和 artifact key。
  • 新增 tests/project-paths.test.mjs，用 Node test runner 验证 key、摘要和未知 key。
  • 把 server/index.js 中的路径函数迁移为模块调用。
  • 提交：refactor: centralize project artifact paths

任务 2：打开文件 API 改为 artifact key

  • 新增 POST /api/videos/:id/open-artifact。
  • 保留旧 open-path 接口为兼容层，前端不再调用。
  • 服务端拒绝未知 key 和未生成路径。
  • 提交：feat: open project artifacts by key

任务 3：前端产物摘要展示

  • 改造 FileResult、DirectoryResult，默认展示短名称。
  • 增加复制完整路径、展开完整路径和打开按钮。
  • 让所有结果行传 artifact key，而不是把绝对路径作为打开参数。
  • 提交：feat: simplify artifact path presentation

任务 4：项目工作目录与环境配置

  • 为新视频记录 workspaceDirectory，默认在 D:\VideoTranslationProjects 下。
  • 新增 data/settings.json 读取逻辑，允许覆盖 VoxCPM Python、Token、临时目录、项目根目录。
  • 保留历史记录兼容：没有 workspaceDirectory 的项目继续按原路径生成。
  • 提交：feat: add project workspace and runtime settings

任务 5：最终验证

  • 运行 npm run test:node。
  • 运行 npm run build。
  • 报告 Python 测试状态，不自动安装 C 盘依赖。
  • 提交：按需提交验证中发现的小修正。
