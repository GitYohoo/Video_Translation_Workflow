持久化任务系统完整迁移实施计划

目标：让全部后台工作流具备持久化状态、稳定 attempt、重启后可诊断、运行中可取消和失败后可重试。

架构：Job Store 负责磁盘状态，Task Registry 负责当前进程内的取消句柄，工作流状态函数合并两者。现有运行接口继续承担重试，不增加重复执行入口。

技术栈：Node.js、Express、React、Node Test Runner、Windows 子进程。

任务 1：扩展 Job Store 状态机

文件：tests/job-store.test.mjs、server/job-store.js

  1. 先写失败测试：任务支持 queued、running、cancelled，重复执行增加 attempt，并可按 videoId 列出任务。
  2. 运行 node --test tests/job-store.test.mjs，确认因为新 API 不存在而失败。
  3. 实现 queueJob、markJobRunning、cancelJob、listJobs，并让所有写入维护 updatedAt。
  4. 运行 Job Store 单测和全部 Node 单测。
  5. 提交 feat: expand persistent job lifecycle。

任务 2：建立可取消任务注册表

文件：tests/task-registry.test.mjs、server/task-registry.js

  1. 先写失败测试：注册任务、读取任务、调用一次取消处理器、已结束任务不可取消。
  2. 运行目标测试确认失败。
  3. 实现 createTaskRegistry()，公开 register/get/finish/cancel。
  4. 运行目标测试和全部 Node 单测。
  5. 提交 feat: add cancellable task registry。

任务 3：统一重启恢复状态

文件：tests/workflow-job-state.test.mjs、server/workflow-job-state.js

  1. 先写失败测试：queued 和 running 在没有内存任务时均解释为 interrupted failed；cancelled 保持 cancelled。
  2. 实现状态合并规则，并保留 attempt、stage、取消原因。
  3. 运行目标测试和全部 Node 单测。
  4. 提交 feat: recover interrupted workflow jobs。

任务 4：迁移剩余后台工作流

文件：server/index.js

  1. 最终字幕、英文配音、单段重配、最终成片启动时写入 running job。
  2. 多阶段英文配音每次切换阶段时持久化 stage。
  3. 完成、失败、取消时分别写入 completed、failed、cancelled。
  4. 状态函数通过 recoverWorkflowTask 合并内存任务和持久化任务。
  5. 运行全部 Node 单测与生产构建。
  6. 提交 feat: persist remaining workflow jobs。

任务 5：统一任务 API 与前端取消入口

文件：server/index.js、src/main.jsx、src/styles.css

  1. 增加项目任务列表、单任务查询和取消 API。
  2. 运行中的工作流卡片显示“取消任务”，调用统一取消 API。
  3. 取消成功后刷新对应工作流状态，显示“已取消，可重新执行”。
  4. 不新增独立重试 API；现有开始/重新生成按钮即重试入口。
  5. 运行全部 Node 单测、生产构建和浏览器关键状态检查。
  6. 提交 feat: control workflow jobs from project UI。
